# ADR-002 : Détection du type réel par magic bytes (python-magic)

**Statut** : Accepté
**Date** : 15/09/2026
**Auteurs** : Marc, Lenny, Mouctar

## Contexte
Le Jalon 1 de Safeguard exige de détecter un "signal faible" : un écart entre
le nom déclaré d'un fichier (son extension, ex. `.pdf`) et son contenu réel.
Le cas test de référence est un fichier Word renommé en `.pdf` pour dissimuler
son vrai contenu ("recette de tarte" cachant un plan confidentiel).

Il fallait choisir une méthode fiable pour déterminer le "vrai type" d'un
fichier, indépendamment de son nom ou de son extension.

## Décision
Utilisation de la bibliothèque `python-magic`, qui lit les "magic bytes"
(octets de signature en début de fichier) pour déterminer le type MIME réel
du contenu, quelle que soit l'extension déclarée.

## Alternatives envisagées
- **Vérifier uniquement l'extension du nom de fichier** : rejeté — c'est
  justement ce qu'un attaquant contourne trivialement en renommant un fichier
  (`plan.docx` → `recette.pdf`). Ne détecte aucun signal faible.
- **Ouvrir et parser complètement chaque type de fichier** (ex. lire l'intégralité
  d'un PDF avec une bibliothèque dédiée, idem pour Word, images...) : rejeté
  pour le Jalon 1 — plus lourd à développer, plus lent à l'analyse, et le
  besoin réel n'est pas de valider l'intégrité complète du fichier mais
  seulement d'identifier son type réel via sa signature.

## Conséquences
**Avantages** :
- Détection rapide et fiable du type réel, basée sur un standard largement
  utilisé (les "magic numbers" utilisés aussi par la commande Unix `file`)
- Fonctionne sans dépendre de l'extension ni du nom du fichier
- Bibliothèque légère, simple à intégrer dans un script Python

**Limites / risques acceptés** :
- Ne détecte que le type de fichier, pas son contenu textuel — un fichier
  cohérent en type (ex. un vrai `.pdf`) mais contenant des données sensibles
  en texte ne sera pas détecté par cette seule méthode (limite à documenter
  dans l'analyse de risque, à traiter par un mécanisme complémentaire si besoin)
- Peut être trompé par des fichiers "polyglottes" très spécifiques
  (fichiers valides pour plusieurs formats à la fois) — cas rare, non traité
  dans le Jalon 1
