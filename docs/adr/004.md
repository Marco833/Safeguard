# ADR-004 : Passerelle mail via Postfix + filtre pipe, retour par port dédié

**Statut** : Proposé (à valider après implémentation et test)
**Date** : 15/09/2026
**Auteurs** : Marc, Lenny, Mouctar

## Contexte
Le Jalon 1 exige une passerelle mail qui analyse automatiquement le contenu
des pièces jointes reçues, sans intervention manuelle. Il fallait choisir un
serveur mail et une méthode d'intégration du script d'analyse dans le flux
de traitement des mails.

## Décision
Utilisation de Postfix comme serveur mail, avec un filtre de contenu de type
`pipe` qui redirige chaque mail entrant vers un script Python. Après analyse,
le mail est renvoyé directement à un second point d'écoute Postfix local
(port 10025, configuré sans filtre) plutôt que via la commande `sendmail`.

## Alternatives envisagées
- **Autre MTA (Exim, Sendmail natif)** : rejeté — Postfix est le standard le
  plus documenté et le plus répandu en environnement Linux, avec un mécanisme
  `content_filter` bien connu pour brancher un script externe.
- **Renvoyer le mail via la commande `sendmail` après analyse** : rejeté après
  test — `sendmail` réinjecte le mail dans le flux normal de Postfix, qui,
  toujours configuré avec le même filtre, le renvoie à nouveau vers le script.
  Résultat observé : boucle infinie jusqu'à l'erreur Postfix `too many hops`
  (limite de 50 relais atteinte).
- **Proxy SMTP externe dédié (ex. Milter custom)** : rejeté pour le Jalon 1 —
  plus complexe à mettre en place qu'un filtre `pipe` simple, pour un gain
  non nécessaire à ce stade du projet.

## Conséquences
**Avantages** :
- Filtre `pipe` simple à comprendre et à déployer (quelques lignes dans
  `master.cf`)
- Le second point d'écoute (port 10025, sans filtre) évite proprement la
  boucle infinie en sortant le mail du circuit filtré après analyse
- Solution 100% locale, cohérente avec la contrainte de souveraineté
  (aucun service mail externe ou cloud)

**Limites / risques acceptés** :
- Configuration Postfix sensible aux erreurs de syntaxe dans `master.cf` —
  nécessite de toujours vérifier avec `sudo systemctl status postfix` après
  chaque modification
- Le filtre traite les mails de façon synchrone (un par un) — un volume très
  élevé de mails simultanés pourrait ralentir la livraison ; non problématique
  pour le périmètre du Jalon 1
- Solution non testée en production, uniquement en environnement de
  développement local à ce stade
